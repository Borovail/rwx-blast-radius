# RWX Blast Radius — план и результаты

## Точка продолжения

Планировщик проверен на 30 примерах и десяти модульных тестах. Следующий шаг — подключить выбор тестов и сравнить его с запуском всех тестов. Репозиторий для отправки пока не настроен.

| Этап | Набор | Simulated, с | Коммиты с пропусками |
| --- | --- | ---: | ---: |
| Стартовый селектор, все 1620 тестов на трёх воркерах | 30 официальных примеров | 1210.470 | 0 |
| Все тесты, LPT и выбор числа воркеров (на этих данных — четыре) | тот же набор | 1104.510 | 0 |

Воспроизведение из корня — команды в `README.md`. На Windows выполнены прямой запуск Python и официальный `score.py`. Значение 1614.1 с на сайте относится к таблице организаторов. Наш локальный показатель рассчитан на опубликованной выборке и исключает CPU.

Модульные тесты планировщика — `python -m unittest discover -s tests -p test_scheduler.py`. Планировщик использует округление миллисекунд из кода официального скорера. Выигрыш этого шага составляет 105.960 с при прежнем выборе тестов.

Проверка на Linux/amd64 в закреплённом Docker-образе с ограничениями организаторов подтвердила оба результата. Для планировщика три запуска дали одинаковые 1104.510 с симуляции. Медиана CPU процесса составила 0.094 с на локальной машине. Команда повторения — `make profile`.

## Этапы

1. Запустить официальный стартовый комплект на 30 патчах. Проверить формат JSONL и число пропущенных коммитов.
2. Сравнить расписания для 1–8 воркеров, сохраняя выбор всех тестов.
3. Построить карту покрытия на SQLGlot `eb11aec4be8cb2122afe713a4816662c3f0fb2fa`. Проверить сопоставление тестов и обработку неполного покрытия.
4. Подключить выбор тестов по патчу. Проверить общие зависимости, импорты, фикстуры и новые строки. Сравнить результат с предыдущим коммитом.
5. Запустить независимые проверки, измерить CPU, повторить сборку с чистого состояния и выбрать коммит для тренировочной отправки.
