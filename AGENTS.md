# RWX Blast Radius

Одна экспериментальная версия — один Git-коммит с понятным названием. В версии проверяем одну гипотезу, сравниваем её с предыдущей на тех же наборах и сохраняем код, связанные тесты и результаты в `PROGRESS.md` одним коммитом. Следующую гипотезу выбираем по результатам этого сравнения.

Координатор делит работу между агентами `gpt-6.1-sol`. Для ограниченных задач подходит `medium`, для анализа и реализации сложных алгоритмов — `high` или `xhigh`. Каждый агент получает конкретную задачу и свои файлы. Координатор интегрирует изменения по очереди, собирает проект, тестирует, профилирует, сравнивает результаты и организует доработку.

Можно использовать подходящие навыки, публичные ресурсы и инструменты в пределах [правил трека](https://www.joinbuilders.org/buildathon/tracks/blast-radius). Для карт покрытия, импортов и фикстур используем закреплённую базовую версию SQLGlot. Эталонные ответы доступны только инструментам оценки. Храним алгоритм независимо от идентификаторов примеров и заранее вычисленных ответов на патчи.

При возобновлении работы читаем `PROGRESS.md` и `git status`. По завершении этапа обновляем в журнале команды воспроизведения, результаты, открытые вопросы и следующий шаг. Отдельно указываем локальные simulated seconds и официальный результат с CPU.

В каждом ответе с версией для отправки на RWX приводим оба поля формы. Под подписью **Public GitHub repository** помещаем URL репозитория, под подписью **Commit** — полный 40-символьный SHA опубликованного коммита выбранной версии. Каждое значение даём отдельным блоком `text` в одну строку, чтобы его можно было скопировать и сразу вставить в форму.

Для сайта RWX используем Browser Use во встроенном браузере Codex (`iab`). Форму, статус и квитанции проверяем в его вкладке через браузерные элементы страницы. В этом проекте запрещено управлять рабочим столом, окнами Windows и личным браузером пользователя. При сбросе браузерной сессии подключаемся к вкладке RWX во встроенном браузере.

На время этой ночной серии пользователь разрешил самостоятельно отправлять проверенные SHA в доступные слоты. После отправки проверяем квитанцию и результат. Обращаемся к пользователю только за решением, которое требует его участия. Перед следующим этапом оцениваем, хватит ли оставшегося лимита на действие целиком, включая проверку и запись результата. По просьбе пользователя прекратить автономную работу сохраняем состояние и останавливаемся.
